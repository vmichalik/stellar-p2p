## The remaining feasibility gate

The MacBook public extension proofs against the mini and Fly, and the two-host setup comparison, have passed. The subsequent owner-approved cloud response check failed after response parsing and disclosure approval. Later platform evidence identifies the server disconnect: Fly stopped the entire verifier VM under its five-minute trial limit at 12:54:26 UTC, exactly when the control connection failed. Separate client callback/disposal errors remain. Read the sanitized timeline and superseding diagnosis in [the handoff](handoff.md#approved-plugin-deployment-and-identified-shutdown).

The owner approved one plugin-only deployment and subsequently reported upgrading Fly to PAYG and adding a card. The pre-upgrade boot still stopped at its trial deadline. After one start of the same VM, a bank-free check observed **391.5 seconds** of continuous uptime with no restart and HTTP 200 health at 13:45 UTC. The former cutoff did not recur during that observation. Bank tests remain paused. Establish HTTP status and JSON structure locally before changing selectors or requesting more fields; the prior Network entry is unavailable.

The plugin currently expects array paths such as `0.amount` and `0.recipient.code`. Those are provisional. A missing field could mean a different shape, an authentication error or a different transaction type; it is not enough evidence to remove the array index.

The exact QuickJS callback-ID overflow was reproduced with shipped assets. The tested plugin mitigation limits repeated header serialization and preserves the disclosure prompt. It was deployed with owner approval on 25 October as image `eb0e1d…`; exact served-code, consent and health checks passed at 13:31 UTC. The extension runtime limit and separate SDK disposal error are not claimed fixed. Local checks pass 93 tests with zero skips; these include actual parser and plugin-host coverage but use synthetic proof results. No new authenticated attempt was made.

An authenticated test passes only when the server verifies the intended completed outgoing transfer, including recipient, amount units, currency, stable ID, time and type. Until then the release gate stays `NOT_CLEARED`.

## Constraints to keep

- Use the pinned extension and verifier versions together.
- Keep the working 4 KiB / 16 KiB proof budgets. Larger budgets exhausted the pinned MPC stream limit in earlier tests.
- Keep cryptographic checks and protocol protections in place. The owner explicitly requested a bounded local diagnostic extension with a 60-second setup watchdog; the official build remains at 30 seconds. The verifier's other deadlines remain unchanged.
- Public checks use GET. The pinned runtime’s method enum supports GET, POST, PUT and DELETE; HEAD is unsupported.
- Never treat a browser callback, screenshot, uploaded receipt or successful setup as authorization to release USDC.

The repo cleanup does not rerun the historical live proof. Current automated check results belong in the development handoff; live claims retain their original observation dates.
