# App presentation contract

Use the browser-safe `@pactlane/payment-policy/presentation` entry point (or `policy/src/presentation.mjs` in the integrated tree). It imports no signing, SDK, SQLite or credential code. `presentPolicyOutcome(outcome, context)` returns fixed state, message-key and suggested-action tokens. App copy, styling and destination links belong to the app owner.

This is presentation only. A mapped result never verifies a payment, establishes escrow balances, authorizes disclosure, signs a claim or permits release. Every output explicitly has `presentationOnly:true`, `automaticRetry:false`, `resendPayment:false`, `releaseAuthorized:false`. A signed policy claim is separate from a confirmed settlement receipt.

## Lifecycle context

The optional context is a small enum-only view from trusted app adapters:

```js
presentPolicyOutcome(errorOrResult, {
  submissionStatus: 'unknown', // 'pending', or omit when no outstanding submission is established
  recoveryStatus: 'awaiting-both-parties', // only from this order's trusted recovery lifecycle
});
```

An outstanding submitted release takes priority over new proof/payment work. Synthetic results keep `evidenceMode:synthetic-only`, including while an outstanding submission is being reconciled. All other outputs use `evidenceMode:not-established`: the mapper never attests that a payment is live verified. Explicit mutual-recovery context is distinct from a generic global policy hold. Errors take priority over conflicting success-result fields. Unknown context strings confer no state, and unknown input values are never reflected in the output.

Never derive `submissionStatus` from `POLICY_ADAPTER_FAILED`, a verifier timeout, an HTTP exception or a lost browser connection. Those may occur before signing or submission. Conversely, once a transaction adapter has recorded submission, a later proof error does not mean it failed. Persist/reconcile the submission in the transaction lane and supply the explicit pending/unknown context here. This package creates no submission record or transaction hash and cannot establish that context itself.

The mapper accepts `PolicyError.code`, a sanitized `errorCode`, or one fixed code string for display. Recognizing a browser callback's code does not authenticate that callback; all execution decisions remain in the trusted policy/transaction adapters. The app must not use `state`, `tone` or `suggestedAction` as an authorization check.

## Domain migration

The website uses `pactlane.io`; the proof service uses its verified Fly origin. Current routes are recorded in the project handoff. The mapper hardcodes no URL or host. The app should build its links from verified deployment configuration.

Do not replace the frozen protocol's `https://app.revolut.com` source-origin namespace with a Pactlane deployment hostname. It identifies the payment source and is part of recipient/nullifier encoding. The claim's signing domain remains the configured Stellar network ID and escrow contract. Changing the product's public hostname requires no change to those frozen protocol bytes.
